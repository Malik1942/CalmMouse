# 用游戏手柄当鼠标

状态：草案，2026-11-17。实测设备：DualSense（PS5 手柄），USB 连接，VID 0x054C / PID 0x0CE6。

## 目标

坐在沙发上，只拿手柄就能操作 Mac：移动光标、点按、右键、拖移、滚动。

- **带触控板的手柄**（DualSense、DualShock 4）：触控板就是主力，用法像笔记本的触控板。
- **没有触控板的手柄**（Xbox、Switch Pro、MFi 等）：左摇杆移动光标，右摇杆滚动。
- 两类手柄的摇杆和按键映射完全一样，DualSense 只是多了一块触控板。

## 不做的（这一版）

- 不做键盘、方向键、快捷键映射（方向键、L1/R1 前进后退之类先不做）。
- 不做按键自定义，映射是固定的。
- 不改手柄灯条，也不做震动反馈。
- 不碰正在玩的游戏：游戏在前台时自动停用（见下文）。

## 操作映射

| 输入 | 动作 |
|---|---|
| 触控板单指滑动 | 移动光标（相对移动，带加速，像触控板） |
| 触控板轻点（单指） | 左键点按 |
| 触控板双指轻点 | 右键点按 |
| 触控板双指滑动 | 滚动（方向跟随系统「自然滚动」设置） |
| 按下触控板 | 左键；按住同时滑动 = 拖移 |
| 双指放在触控板上按下 | 右键 |
| 左摇杆 | 移动光标（推得越深越快） |
| 右摇杆 | 滚动（上推 = 往上滚） |
| 按下左摇杆（L3） | 左键；按住再推 = 拖移 |
| 按下右摇杆（R3） | 右键 |
| ✕ / A（下方按键） | 左键；按住 + 移动 = 拖移；快速连按 = 双击 |
| ○ / B（右侧按键） | 右键 |
| 同时按住 Options + Create（Xbox：≡ + ⧉）半秒 | 开 / 关「用手柄当鼠标」 |

点按的连击数（双击、三击）按系统的双击速度计算，和 CalmMouse 现有的轻点逻辑一样。

**为什么按摇杆当点按，以及右键怎么放才自然。** 用摇杆移动光标时，拇指本来就在左摇杆上，就地按下去点按最顺手，像在鼠标上用手指点一下。右键放在右摇杆上，左右两根摇杆正好对应鼠标的左右键，好记，而且右手拇指平时就搭在右摇杆上。考虑过但没选的方案：长按左摇杆当右键（要等，而且和按住拖移冲突）；L1 / R1 当左右键（食指要离开扳机，对只用拇指操作的人不顺）。

**防抖。** 按下摇杆时几乎一定会把它往旁边带一点，松开时也会。所以按下和松开后的 0.15 秒内，忽略这根摇杆的推动，光标停在要点的东西上，右摇杆也不会顺带滚动页面。按住超过这段时间再推，就是拖移。另一根摇杆不受影响。

这一项默认开，可以在设置里关掉（「按下摇杆来点按」）。有的手柄摇杆按键很松，关掉可以避免误点。

## 开关和自动停用

- 总开关「用手柄当鼠标」**默认关**。理由：已经在用手柄玩游戏的用户更新后行为不能变（和滚轮鼠标那次的原则一致）。
- 开启方式有三个，改的是同一个设置：
  1. 菜单栏菜单里的「用手柄当鼠标」（只在连着手柄时出现，属于常切换的开关，放菜单栏）；
  2. 设置 → 设备 → 手柄；
  3. 手柄上同时按住 Options + Create 半秒（开 / 关时各响一声系统提示音）。
- **游戏在前台时自动停用**：前台 App 的类别是游戏（`LSApplicationCategoryType` 为 `public.app-category.games` 或任一 `*-games`），手柄输入全部不处理。这个设置默认开，可以关掉。
- CalmMouse 整体暂停时，手柄也一起停。

## 设置界面

手柄作为一个设备出现在「设备」页的设备列表里（图标 `gamecontroller`，名称取手柄自己的名字，右边显示电量）。选中后右侧这几行：

- 用手柄当鼠标（开关）
- 指针速度（滑块，慢 ↔ 快）
- 滚动速度（滑块，慢 ↔ 快）
- 轻点触控板来点按（开关，默认开；只在手柄有触控板时显示）
- 按下摇杆来点按（开关，默认开）
- 游戏在前台时停用（开关，默认开）

每行的说明放在左侧悬停说明里（沿用现有 `ExplainedRow`），不在行下加小字。中英繁三种语言都要翻译。

## 手感参数（初始值，实机再调）

- **触控板**：坐标是 −1…1 的归一化值。DualSense 触控板物理宽高比约 1920 : 1080，所以 y 方向的位移乘 0.5625，横竖手感一致。默认速度下一次划过整块板宽约移动 700 pt，快速划动再按速度加速。手指刚落下的第一帧不产生位移（避免跳一下）。
- **轻点**：接触时间 ≤ 0.2 s 且总位移 ≤ 板宽的 3% 算轻点。
- **摇杆**：径向死区 0.12；速度 = 最大速度 × ((偏移 − 死区) / (1 − 死区))²，默认最大速度 1600 pt/s；只在摇杆推着的时候按 120 Hz 更新，松开即停，不占 CPU。
- **右摇杆滚动**：同样的曲线，默认最大 1500 px/s，发像素级滚动事件。
- **光标边界**：不会移出所有屏幕的范围；跨屏时按屏幕实际排列走。

## 连接方式：有线、2.4G、蓝牙

CalmMouse 不看连接方式。手柄都通过 Apple 的 GameController 框架读取，有线、蓝牙、2.4G 接收器（在 macOS 看来就是一个 USB 设备）走的是同一条路。能不能认出来，取决于 macOS 支不支持这款手柄：

- 支持：DualSense、DualShock 4、Xbox One / Series、Switch Pro、MFi 手柄，以及 macOS 13 起的大多数通用 HID 手柄（`GCProductCategoryHID`），2.4G 接收器多半属于这一类。
- 不支持：微软自家的 Xbox 无线适配器，以及固定在 Xbox 360（XInput）模式的接收器。macOS 没有这两种的驱动，任何 App 都读不到。很多第三方手柄可以切到 Switch 或 D-input 模式，切过去就能用。

为了能排查，`--status` 里每个手柄都带上连接方式（`transport=USB` / `Bluetooth`），macOS 列出来但读不了的手柄单独列在 `unsupportedControllers`。

几个跟连接有关的细节：

- 手柄断开时（比如拔掉线改用蓝牙），立刻松开所有按着的键，不会留下一个一直按着的左键。
- 同一个手柄同时插线又连着蓝牙、或者两只同型号手柄，设备列表里各占一行，并标出各自的连接方式。所有手柄共用一套设置。
- 按键状态按手柄分开记，两只手柄同时用不会互相干扰。

实测：DualSense 有线（USB）通过；蓝牙见下方验证；2.4G 没有实物，未经实机验证。

## 实现结构

- `CalmMouseCore/ControllerPointer.swift`（纯逻辑，可单测）：输入是触控板接触、摇杆值、按键、时间；输出是「移动 / 滚动 / 按下 / 抬起 / 点按」动作。轻点识别、拖移、双击计数、死区和曲线都在这里。
- `CalmMouse/GamepadController.swift`：用 Apple 的 GameController 框架（`shouldMonitorBackgroundEvents = true`，CalmMouse 不在前台也能收到输入）读手柄，喂给核心逻辑，再把动作变成 CGEvent 发出去（和现有轻点点按一样走 `.cghidEventTap`，带 CalmMouse 自己的标记，事件监听不会把它们当成 Magic Mouse 的操作）。
- `MouseEnvironment` 里多一份已连接的手柄列表，设置窗口和菜单都从这里读。
- `--status` 里多几项：连着的手柄、是否在接管、发出的事件数，方便排查。

## 验证

- 核心逻辑单测：触控板移动与跳帧、轻点和非轻点、双指滚动、按住拖移、摇杆死区和曲线、组合键开关。
- 实机：用这台 DualSense 走一遍上面整张映射表；Xbox 手柄没有实物，靠「无触控板」这条路径的单测覆盖，并在说明里注明未经实机验证。
